# Appendix B. Gaps in the Testing Tools

Where a Testing Tool lacks something the Unified API needs, its adapter fills the gap and a ticket tracks closing it in the tool itself (map Notes rule). Gaps in Dramafinder have their own issues in `parttio/dramafinder`; gaps in TestBench and Browserless are checklists on one ticket each.

## Dramafinder

| Gap | Issue |
|---|---|
| No typed query builder `find(X.class).withLabel(..).single()` | [parttio/dramafinder#200](https://github.com/parttio/dramafinder/issues/200) |
| Label lookups match substrings by default | [parttio/dramafinder#201](https://github.com/parttio/dramafinder/issues/201) |
| No server round-trip wait after most actions | [parttio/dramafinder#202](https://github.com/parttio/dramafinder/issues/202) |
| Id and test id lookups missing on most elements | [parttio/dramafinder#203](https://github.com/parttio/dramafinder/issues/203) |
| No navigation by route class, no location assertions | [parttio/dramafinder#204](https://github.com/parttio/dramafinder/issues/204) |
| Spring Boot integration generated by the skill, not shipped | [parttio/dramafinder#205](https://github.com/parttio/dramafinder/issues/205) |

## TestBench

[TestBench: close the gaps with the Unified API](https://github.com/jcgueriaud1/unified-testing-tool/issues/21): no element-state wait before actions, no retrying assertions, no accessible-name lookup, filters not per type, test id only from 25.4, elements can go stale, deprecated `first()` in docs, no route-class navigation, no documented Spring Boot test integration.

## Browserless Test

[Browserless Test: close the gaps with the Unified API](https://github.com/jcgueriaud1/unified-testing-tool/issues/22): no accessible-name filter, few type-specific filters, background work needs manual flushing, no retrying assertions, no generated typed locators for custom testers.
