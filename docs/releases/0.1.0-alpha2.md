# 0.1.0-alpha2

Second alpha of the Unified API for Vaadin UI tests. It closes the gaps found while porting the 205 UI
tests of a Spring Boot app to `0.1.0-alpha1` ([#80](https://github.com/parttio/unified-testing-tool/issues/80)
to [#96](https://github.com/parttio/unified-testing-tool/issues/96)): tests that passed on one Testing Tool and
failed on another, missing Core Set components, and slow browser runs.

The API can still change between alphas. Some changes below change what a test sees; see **Behaviour changes**.

## Get it

On Maven Central as `org.vaadin.addons:*:0.1.0-alpha2`. Import `unified-test-bom` and add the adapters you
run on as test dependencies (see [Try it](https://parttio.github.io/unified-testing-tool/#try-it)).

Requires Java 21, Vaadin 25.3 and, for `@UnifiedSpringBootTest`, Spring Boot 4.1.

## Behaviour changes

- **Hidden components are found on every tool** ([#88](https://github.com/parttio/unified-testing-tool/issues/88)).
  Browserless used to skip them while browsers included them. Add the new `.visible()` filter for checks like
  "the action is gone".
- **`getText()` is the DOM text on every tool** ([#84](https://github.com/parttio/unified-testing-tool/issues/84)):
  `textContent` with whitespace collapsed, so `text-transform`, hidden descendants and flex line breaks no
  longer change it. `withText` uses it too. The rendered text is `getVisibleText()` (browsers only).
- **`findChildren(tag)` returns direct light-DOM children on every tool** ([#87](https://github.com/parttio/unified-testing-tool/issues/87)).
  It used to return every descendant in a browser. New: `children()` and `findDescendants(tag)`.
- **A query for a component with no tag fails on every tool** ([#86](https://github.com/parttio/unified-testing-tool/issues/86)),
  not only in a browser.
- **A `@Transactional` `@UnifiedSpringBootTest` fails on browser tools** ([#81](https://github.com/parttio/unified-testing-tool/issues/81)),
  before it starts, with the reason: the views run outside the test's transaction there. See "Test data" in
  the spec's test setup chapter.
- **Selenium reuses one browser per run** ([#96](https://github.com/parttio/unified-testing-tool/issues/96)).
  Each test still starts in a fresh tab with no cookies or storage. `vaadin.testing.selenium.reuse-browser=false`
  restores a browser per test.
- **Browser queries leave out the shadow DOM of Vaadin's components and dev tools**, and match open dialogs
  only ([#89](https://github.com/parttio/unified-testing-tool/issues/89)).

## New

- **Core Set** ([#93](https://github.com/parttio/unified-testing-tool/issues/93)): `UnifiedTextArea`,
  `UnifiedIntegerField`, `UnifiedBigDecimalField`, `UnifiedDateTimePicker`, `UnifiedTabs`, `UnifiedDetails`,
  `UnifiedMenuBar` (`clickItem("File", "Export", "PDF")`) and `UnifiedUpload` (`upload(name, type, bytes)`), with
  assertions. Plain HTML Scopes: `UnifiedDiv`, `UnifiedSpan`, `UnifiedSection` and more. A `findComponent(..)`
  result is a Scope. `UnifiedDatePicker.typeText(..)` types text the field may not parse.
- **`@UnifiedComponent(selector = ".metric-card")`** ([#86](https://github.com/parttio/unified-testing-tool/issues/86)):
  a default filter every tool applies, for a component built from a common layout.
- **`getInlineStyle(name)`** returns the declared inline style (`var(--gap)`) on every tool ([#84](https://github.com/parttio/unified-testing-tool/issues/84)).
- **`vaadin.testing.browserless.route-errors-to-session=true`** sends a listener's exception to the session's
  `ErrorHandler`, as in a browser ([#92](https://github.com/parttio/unified-testing-tool/issues/92)).
- Generic `hasText(..)` / `hasTextContaining(..)` assertions on every wrapper.
- On Selenium, MenuBar, Upload, DateTimePicker and Details go through TestBench's element classes
  (`vaadin-menu-bar-testbench`, `vaadin-upload-testbench`, `vaadin-date-time-picker-testbench`,
  `vaadin-details-testbench`, now dependencies of `unified-test-selenium`) ([#104](https://github.com/parttio/unified-testing-tool/issues/104)).

## Fixed

- Selenium: an element Vaadin re-renders during a find or an action no longer fails the test with
  `StaleElementReferenceException`; the query runs again within the timeout ([#95](https://github.com/parttio/unified-testing-tool/issues/95)).
- Browserless under `@UnifiedSpringBootTest` finds every route of the Spring Boot app, not only those in the
  test's package ([#82](https://github.com/parttio/unified-testing-tool/issues/82)), and fails at once with the
  dependency to add when `browserless-test-spring` is missing ([#94](https://github.com/parttio/unified-testing-tool/issues/94)).
- Browserless finds a field named with `setAriaLabel(..)` by its accessible name ([#90](https://github.com/parttio/unified-testing-tool/issues/90)),
  and components in Grid cells with a page-wide find ([#83](https://github.com/parttio/unified-testing-tool/issues/83)).
- Playwright `isAt` sees a RouterLink navigation, and `isAt` works for a view with no route, such as a custom
  not-found view ([#91](https://github.com/parttio/unified-testing-tool/issues/91)).
- `setValueAsUser` on a native `<input>` works on every tool ([#80](https://github.com/parttio/unified-testing-tool/issues/80)).
- Playwright and Selenium check class, theme and attribute filters in one query instead of one browser round
  trip per element, and no longer wait out the timeout on an element that detaches mid-check ([#85](https://github.com/parttio/unified-testing-tool/issues/85)).
- A BigDecimal value is typed with its scale (`54.20`, not `54.2`).

## Known limitations

- Browserless: searching inside Grid row details (`row.details()`) throws; toggling and checking details works.
- Browserless: `page.reload()`, `pressKey` and `dispatchEvent` are simulated; client-side behaviour (typing text,
  Tab moving focus) doesn't happen ([#66](https://github.com/parttio/unified-testing-tool/issues/66)).
- Browserless: deselecting one item of a MultiSelectComboBox is done on the server, not as from the client
  ([#61](https://github.com/parttio/unified-testing-tool/issues/61)).
- Browser: a combo box's `getItems()` returns the drop-down's first page only (50 items by default).
- A component that was never visible is in no browser's page but Browserless finds it; `.visible()` gives the
  same answer everywhere. Browserless Test and TestBench disagree on this too ([#97](https://github.com/parttio/unified-testing-tool/issues/97)).
- `UnifiedDateTimePicker` has no `typeText(..)` yet: Browserless can't type into one half of the picker.
