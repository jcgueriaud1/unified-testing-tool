# PROTOTYPE: the same test in Dramafinder, TestBench, Browserless and the Unified API

Scenario: fill a name, save, check notification and field, open a confirm dialog from an icon-only
button and click Delete inside it. Method names checked against each library's sources
(Dramafinder 1.2.x, TestBench 25.3, Browserless Test 25.3); spots not verified are marked.

## 1. Dramafinder (Playwright)

```java
class ProfileViewIT extends SpringPlaywrightIT {          // generated by Dramafinder's skill
    @Override public String getView() { return "profile"; }

    @Test
    void savesNameAndDeletes() {
        TextFieldElement name = TextFieldElement.getByLabel(page, "Name");  // substring match by default
        name.setValue("Alice");
        ButtonElement.getByText(page, "Save").click();      // no server wait after click

        NotificationElement.getByText(page, "Saved Alice").assertOpen();
        name.assertValue("Alice");                           // retrying assertion
        name.assertValid();

        ButtonElement.getByLabel(page, "Delete account").click();   // accessible name
        DialogElement dialog = DialogElement.getByHeaderText(page, "Delete account?");
        ButtonElement.getByText(dialog.getLocator(), "Delete").click();  // scope = a Locator
        dialog.assertClosed();                               // (name assumed)
    }
}
```

## 2. TestBench (Selenium)

```java
class ProfileViewIT extends BrowserTestBase {
    @BrowserTest
    void savesNameAndDeletes() {
        getDriver().get("http://localhost:8080/profile");

        TextFieldElement name = $(TextFieldElement.class).withLabel("Name").single();
        name.setValue("Alice");
        $(ButtonElement.class).withText("Save").single().click();   // waits for server round-trip

        NotificationElement notification = $(NotificationElement.class).waitForSingle();
        assertEquals("Saved Alice", notification.getText());       // no retry
        assertEquals("Alice", name.getValue());
        assertFalse(name.isInvalid());

        $(ButtonElement.class).withAttribute("aria-label", "Delete account").single().click();
        DialogElement dialog = $(DialogElement.class)
                .withPropertyValue(DialogElement::getHeaderTitle, "Delete account?").single();
        dialog.$(ButtonElement.class).withText("Delete").single().click();  // scope = element
        assertFalse(dialog.isOpen());
    }
}
```

## 3. Browserless

```java
@ViewPackages(classes = ProfileView.class)
class ProfileViewTest extends BrowserlessTest implements Locators {
    @Test
    void savesNameAndDeletes() {
        navigate(ProfileView.class);                         // by route class, no server

        findTextField().withLabel("Name").setValue("Alice"); // locator acts directly, no single()
        findButton().withText("Save").click();               // synchronous

        assertEquals("Saved Alice", findNotification().getText());
        TextField name = findTextField().withLabel("Name").component();  // the real Flow component
        assertEquals("Alice", name.getValue());
        assertFalse(name.isInvalid());

        findButton().withAriaLabel("Delete account").click();
        var dialog = findDialog()
                .withCondition(d -> "Delete account?".equals(d.getHeaderTitle()), "header");
        findButton().withText("Delete").inside(dialog).click();  // scope = inside(...)
        assertFalse(dialog.component().isOpened());
    }
}
```

## 4. Unified API (as decided so far; entry object name and navigation still open)

```java
@UnifiedUITest
class ProfileViewTest {
    @Test
    void savesNameAndDeletes(UI ui) {
        ui.navigate("profile");                              // open: "How does a test open a view?"

        UnifiedTextField name = ui.find(UnifiedTextField.class).withLabel("Name").single();
        name.setValue("Alice");
        ui.find(UnifiedButton.class).withText("Save").single().click();  // Auto-Wait everywhere

        assertThat(ui.find(UnifiedNotification.class).single()).isOpen().hasText("Saved Alice");
        assertThat(name).hasValue("Alice").isValid();        // retrying on every Testing Tool

        ui.find(UnifiedButton.class).withAccessibleName("Delete account").single().click();
        UnifiedDialog dialog = ui.find(UnifiedDialog.class).withHeaderTitle("Delete account?").single();
        dialog.find(UnifiedButton.class).withText("Delete").single().click();  // scope = wrapper
        assertThat(dialog).isClosed();
    }
}
```

## Where the Unified API sits

| Aspect | Closest to | Differs from |
|---|---|---|
| `find(X.class).withLabel(..).single()` | TestBench `$(X.class)…single()` | Dramafinder (static factories per class), Browserless (`findX()`, no `single()`) |
| Lazy wrapper that acts directly | Browserless locators, Dramafinder (Playwright locators) | TestBench (resolved once, can go stale) |
| Scoping `dialog.find(...)` | TestBench `dialog.$(...)` | Dramafinder (`getByText(dialog.getLocator(), …)`), Browserless (`.inside(dialog)`) |
| `withAccessibleName` | Dramafinder `getByLabel` (role + name) | TestBench (`withAttribute("aria-label")`), Browserless (`withAriaLabel`, aria-label only) |
| Per-type filters like `withHeaderTitle` | Browserless per-type filter mixins | TestBench and Browserless need `withPropertyValue` / `withCondition` |
| Retrying `assertThat(x).hasValue()` | Dramafinder `assertValue`, in AssertJ style | TestBench, Browserless (`assertEquals` on getters, no retry) |
| Waiting before and after every action | TestBench (server) + Dramafinder (element) combined | each alone covers only half |
| Test class setup | Browserless extension style | TestBench and Dramafinder base classes, `@BrowserTest` |

TestBench users recognise the lookup grammar; Dramafinder users the behaviour (lazy wrappers,
accessible names, retrying assertions); Browserless users the per-type filters and JUnit
integration. The real departures: `Unified*` names, `withAccessibleName` on every type, and
Auto-Wait on both sides of every action on every Testing Tool.
